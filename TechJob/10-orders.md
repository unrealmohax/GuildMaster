## Цель

Заказы появляются каждое утро, Регистратор ставит обычные на доску по правилам игрока, важные передаёт игроку. У гильдии появляется репутация, от которой зависит поток заказов и кандидатов.

## Опирается на

- GM-01: команды. GM-02: `QuestTypeDefinition`, `OrderTextTemplates`, `BalanceSettings.Orders`. GM-03: утро, дни.
- GM-04: ранги людей, шанс кандидата. GM-07: лента, падежи и род названий. GM-09: отчёт месяца.

## Репутация гильдии

- `Guild.Reputation` — float 0..100, старт — `Guild.startReputation` (5). Меняется службой `ReputationService` (изменить на Δ с причиной, в лог).
- В этом ТЗ репутация не меняется; от неё зависят количество и ранги заказов и шанс кандидата.

## Модель данных `Order`

| Поле | Что это |
|---|---|
| `Id`, `TypeId` | Охота, истребление, сопровождение, доставка |
| `Client` | Заказчик (горожанин, купец, крестьянин — из `OrderTextTemplates`) |
| `Place`, `Enemy`, `Cargo` | Место, враг, груз — из `OrderTextTemplates`, для описания и ленты |
| `Rank` | G–C |
| `Profile` | float[13] — скрытый профиль требований по осям диаграммы |
| `PartySizeCeiling`, `StatCeilings` | Скрытые потолки |
| `Description`, `HintStats` | Текст для игрока и людей, какие оси в нём намекнуты |
| `DescriptionAccuracy` | Скрытый множитель 0,9–1,1: насколько описание недооценивает / переоценивает задание |
| `Reward`, `Surcharge` | Награда заказчика и доплата гильдии |
| `Distance` | `Near` / `Far` |
| `ExpiresAtHours` | Когда снимут с доски |
| `Status` | `Incoming` → `OnBoard` / `AwaitingPlayer`; `Declined`, `Expired`. Список статусов расширяемый |
| `Flags` | `IsImportant`, `IsHardEarly` (сложный не по времени) |

## Генерация (каждый день в 06:00)

1. **Количество**: `1 + репутация / 10`; дробная часть — шанс ещё одного заказа.
2. **Ранг** по смеси для текущей репутации ❔:

| Репутация | G | F | E | D | C |
|---|---|---|---|---|---|
| 0–20 | 85% | 15% | — | — | — |
| 20–40 | 20% | 50% | 30% | — | — |
| 40–60 | — | 10% | 50% | 40% | — |
| 60+ | — | — | 20% | 50% | 30% |

   С шансом **5%** заказ — **сложный не по времени**: ранг +2 к выпавшему (не выше C).
3. **Тип** ❔: охота 30%, истребление 25%, сопровождение 20%, доставка 25%.
4. **Расстояние** ❔: близко 70%, далеко 30%.
5. **Профиль**: главные оси типа — `Range(главные[ранг])`, второстепенные — `Range(второстепенные[ранг])`, остальные — 0; каждая ось × `Range(0,8; 1,2)`; затем **все оси не меньше `Orders.requirementFloor` (10)**. ❔ Далеко: если Выживания нет среди осей — добавить как второстепенную.
   - Зачем порог: шанс задания считается по площади фигуры из соседних осей; без порога требуемая ось с нулевыми соседями не давала бы площади. 10 — естественный минимум параметров человека (GM-04).
6. **Потолки**: из типа. В прототипе потолков нет ни у одного типа (доставка — тоже, решение 2026-09-26), но поле остаётся.
7. **Награда**: `Range(награда[ранг])`, далеко × 1,5, округлить до 5.
8. **Срок на доске**: 3–7 дней.
9. **Описание** (ниже), `DescriptionAccuracy = Range(0,9; 1,1)`.
10. **На старте игры** ❔ — 3 заказа ранга G уже на доске.

Шаблоны профилей по типам — [quests.md](../docs/mechanics/quests.md#генерация-заказов). Генерация профиля — отдельная функция «тип + ранг → профиль».

## Описание

- Шаблон из `OrderTextTemplates` для типа: «{заказчик} просит {действие} у {место:р}».
- **Намёки** на 1–2 самые большие оси профиля (строки на каждую ось в `OrderTextTemplates.hints`):

| Ось | Пример намёка |
|---|---|
| Наблюдательность | «Говорят, зверь хитёр и осторожен» |
| Сила / Выносливость | «Их там целая стая» |
| Меткость | «Близко к нему не подойти» |
| Знания | «Никто толком не знает, что это за тварь» |
| Выживание | «Дорога идёт через глушь» |
| Реакция | «Нападает внезапно» |
| Скрытность | «Лишнего внимания не нужно» |

- Далеко — «Путь неблизкий». Задание с потолком размера — «Лишнего внимания не нужно» (в прототипе потолков нет).
- ❔ 30 строк намёков — черновик, заполняет автор.
- **Названия для ленты**: у заказчиков, мест, врагов, грузов в `OrderTextTemplates` — шесть падежных форм и род (`NounForms`, GM-07). Заполнить.

## Регистратор и важные заказы

- **Важный заказ** ❔: `IsHardEarly` или награда ≥ `importantRewardThreshold` (250).
- **Обычный заказ** Регистратор проверяет по **правилам игрока** (команда `SetRegistrarRules`):
  - какие типы брать (переключатели по 4 типам);
  - до какого ранга брать сам;
  - минимальная награда.
  Подходит → `OnBoard`. Не подходит → `Declined` (строка в ленте гильдии [О]).
- **Важный заказ** → `AwaitingPlayer`: событие [В], игрок **принимает** (можно сразу назначить доплату) или **отклоняет** — команда `AnswerImportantOrder(orderId, accept, surcharge)`. ❔ Без ответа 2 дня — отклонён.

## Доска

- Игрок видит: тип, заказчик, ранг, расстояние, награда, доплата, описание, сколько осталось висеть. **Профиль не виден никогда.**
- Игрок может **назначить доплату** любому заказу на доске — команда `SetSurcharge(orderId, amount)`. Доплата — обещание: деньги из казны сейчас не списываются.
- Непопулярный заказ снимается по сроку: `Expired`. В прототипе все заказчики — горожане, последствий нет.

## Доработка готового кода

- **GM-04, шанс кандидата**: в `RecruitSystem.CandidateChance` брать `Guild.Reputation` вместо `Guild.startReputation`.
- GM-06: бот «Простой» — Регистратор берёт все типы до высшего ранга людей гильдии, без порога награды; важные заказы принимает, если в гильдии есть человек этого ранга. В лог — профиль заказа и `DescriptionAccuracy` (`Debug`). В сводку — заказов пришло / на доску / отклонено Регистратором / отклонено игроком / снято по сроку, репутация на конец месяца.
- GM-07: строки — новые заказы на доске, отклонён Регистратором, важный заказ ждёт решения, снят по сроку.
- GM-09: в отчёт месяца — раздел «Заказы»: сколько пришло, какие сняты и отклонены; раздел «Репутация»: было → стало.

## Критерии приёмки

- [ ] Заказы появляются в 06:00 в нужном количестве и смеси рангов по репутации.
- [ ] Профиль собирается по шаблону типа, все оси не ниже порога, скрыт от игрока.
- [ ] Описание содержит намёки на главные оси.
- [ ] Регистратор ставит на доску по правилам, важные уходят игроку, без ответа — отклоняются.
- [ ] Доплата назначается командой и хранится в заказе.
- [ ] Просроченные заказы снимаются.
- [ ] Шанс кандидата зависит от текущей репутации.

## Открытые вопросы

- ❔ Смесь рангов по репутации, доли типов и расстояний, порог «важного», срок ответа игрока, стартовые заказы.
- ❔ Тексты намёков.
