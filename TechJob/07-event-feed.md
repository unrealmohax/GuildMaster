# GM-07. Лента событий

| Задача | Ветка | Метки коммитов |
|---|---|---|
| **GM-07** | `GM-07_event_feed` | `[GM-07]` — код, `[TechSpec-07]` — правки этого ТЗ |

Дизайн: [quests.md → Лента событий](../docs/mechanics/quests.md#лента-событий). Шаблоны: [event-feed.md](../docs/content/event-feed.md).

## Цель

Превращать события симуляции в короткие строки-хронику на русском: лента гильдии, три уровня важности, варианты по чертам и архетипу, правильные падежи и род, без выдачи скрытых черт.

## Опирается на

- GM-01: `SimEvent`, шаг такта `FeedSystem` — 15-й, после всех систем, которые публикуют события, и перед `AutopauseSystem` (решение 2026-09-27).
- GM-02: `FeedTemplateSet`, `NameList`, словарь меток `TextPlaceholders`, валидатор данных.
- GM-03: важность событий и автопауза.
- GM-04, GM-05: события людей, раскрытие черт.
- GM-06: `SimLogger`.

## Модель данных `FeedEntry`

| Поле | Что это |
|---|---|
| `TimeHours` | Когда |
| `Feed` | Лента; сейчас одна — `Guild` |
| `Importance` | `Normal` [О], `Notable` [З], `Important` [В] |
| `Text` | Готовая строка |
| `Links` | Id людей и других объектов строки — для перехода по клику |
| `TemplateKey` | Для отладки |

- ❔ Лента гильдии хранит последние 500 строк (`BalanceSettings.Feed.guildFeedLimit`).

## Путь от события к строке

1. Система публикует `SimEvent`.
2. `FeedSystem` по типу события берёт **ключ шаблона**. Событие без ключа строки не даёт.
3. Выбирает `FeedTemplate` по ключу, у которого выполнены **условия**; если подходят несколько — самый конкретный (больше условий).
4. Выбирает **случайный вариант** строки; ❔ не повторять последний использованный вариант этого ключа.
5. Подставляет значения, склоняет, ставит род.
6. Пишет строку в ленту и в лог (`Info`).

## Условия шаблонов

| Условие | Пример |
|---|---|
| `Archetype(x)` | Вариант для Щита |
| `RequiresRevealed(черта или полюс)` | Строка, которая называет черту прямо |

- Набор условий — расширяемый: условие — имя и проверка по событию.
- **Скрытые черты не выдаются**: строка с условием `RequiresRevealed` выбирается только если черта уже раскрыта. Для нераскрытой — вариант, описывающий только поведение.

## Подстановки

| Метка | Что | Примечание |
|---|---|---|
| Метки людей: `{имя}`, `{напарник}`, `{лекарь}`, `{щит}`, `{решающий}` | Люди из события | Склоняются, задают род |
| Метки названий: `{место}`, `{враг}`, `{заказчик}`, `{груз}`, `{группа}`, `{распоряжение}`, `{постройка}` | Названия из данных | Склоняются, у каждого свой род |
| `{число}`, `{сумма}` | Числа | |

- Движок подстановки общий: метка → источник значения из события. Метка без источника в событии — ошибка в лог (`Error`) и строка без подстановки: строка всё равно попадает в ленту, а метка остаётся в ней как есть (решение 2026-09-27).
- Сейчас в событиях есть только люди и числа; остальные метки проверяются тестами на тестовых названиях.

### Падежи

В русских строках нужны падежи: «у {место}» → «у старой мельницы», «рядом с {напарник}» → «рядом с Марой», «У {имя}» → «У Яна».

- Метка с падежом: `{имя:р}` (родительный), `{имя:д}` (дательный), `{имя:в}` (винительный), `{имя:т}` (творительный), `{имя:п}` (предложный). Без буквы — именительный.
- ❔ У имён и названий в данных хранятся **все шесть форм** (`NounForms`). В этом ТЗ — заполнить формы у всех имён `NameList`.
- **Расставить падежи в шаблонах** [event-feed.md](../docs/content/event-feed.md) и в ассете `FeedTemplateSet` — во всех, не только в строках событий GM-03–05. Например: «до {место:р}», «у {место:р}», «на {враг:в}», «рядом с {напарник:т}», «закрыл собой {напарник:в}», «У {имя:р} рассечена бровь», «без [него|неё]».

### Род

- Скобки `[м|ж]` — форма для мужского и женского рода: `заметил[|а]`, `испугал[ся|ась]`, `[он|она]`, `[его|её]`.
- **Чей род**: ближайшего **предыдущего** человека-метки в том же предложении; если перед скобкой человека нет — ближайшего **следующего**.
- Явное указание: `[его|её]@имя` — род `{имя}`. Нужно, например, в «{напарник} тащит [его|её]@имя на себе».
- ✅ **Род у названий** (решение 2026-09-26): у названий в данных хранится род — мужской, женский, средний или множественное число (`NounForms.gender`). Скобка для них — три или четыре формы `[м|ж|ср]` / `[м|ж|ср|мн]` и **всегда** явная привязка: «{постройка} готов[|а|о]@постройка» → «Общежитие готово», «Таверна готова». Без `@` скобка относится к человеку и имеет две формы. Нет нужной формы в скобке (например, мн при трёх формах) — берётся мужская.
- ❔ `{группа}` — всегда в форме «группа {имя:р}» или «группа «{название}»» — женский род, единственное число: «группа «Серые волки» вышла».
- Валидатор (GM-02) проверяет, что у каждой скобки находится человек. Сейчас он даёт 17 предупреждений о скобках без человека — исправить шаблоны, чтобы предупреждений не осталось.

## Уровни важности

| Уровень | Автопауза |
|---|---|

| [З] заметное | Нет |
| [В] важное | Если тип события в списке автопаузы (GM-03) |

## Строки раскрытия черт

- Раскрытие — всегда [В]. Строка — из таблицы раскрытия в [event-feed.md](../docs/content/event-feed.md#раскрытие-черт), ключ — `revealFeedKey` полюса или черты (GM-02).

## Строки событий GM-03–05

Каждое событие GM-04 и GM-05, для которого есть строка в [event-feed.md](../docs/content/event-feed.md), даёт строку в ленте гильдии: кандидат пришёл / ушёл, человек вступил, смена архетипа, раскрытие черт и «уравновешен», срыв, запой, уход из гильдии, пустой кошелёк, конец горя (Потерявший товарища). Строки для систем, которых в event-feed.md не было, предложены в GM-02 (💡 [event-feed.md → Новые строки](../docs/content/event-feed.md#-новые-строки-gm-02-на-утверждение)) — взять их.

### Какое событие какую строку даёт (решение 2026-09-27)

| Событие | Ключ | Важность |
|---|---|---|
| Кандидат пришёл / ушёл без ответа | `guild.candidate.arrived` / `.left` | [О] |
| Человек вступил | `guild.adventurer.joined` | [О] |
| Смена архетипа | `guild.archetype.changed` | [О] |
| Раскрытие полюса / черты | `revealFeedKey` из данных | [В] |
| «Уравновешен» | `balancedFeedKey` оси — новая строка на каждую ось | [З] |
| Срыв | `guild.breakdown.binge` / `brawl` / `brawlAlone` (драка, когда рядом никого) / `refuse` / `collapse` — новая строка на каждый вид | [В] |
| Уход из гильдии | `guild.adventurer.left` | [В] |
| Пустой кошелёк | `guild.money.walletEmpty` | [З] |
| Рана зажила — только последняя | `guild.health.recovered` | [О] |
| Осложнение раны | `guild.health.complication` — строка без Лекаря («Лежит в жару») | [З] |

- «Запой» — срыв-запой; повторный пропуск дня Пьяницы строки не даёт (первый раскрывает черту — строка раскрытия).
- Конец горя — только строка раскрытия «Потерявшего товарища»; итог «сломался / ожесточился» строки не даёт.
- Отказ кандидату, приобретение черты (она скрыта), повышение ранга строк не дают — строк для них в event-feed.md нет.

## Допущения реализации (GM-07)

- ❔ **Важность строки** — из шаблона; тест сверяет её с важностью события.
- ❔ **Не повторять вариант** — лента помнит последний вариант каждого ключа (часть мира). Случайное число тянется своим потоком `FeedSystem`, и только если вариантов больше одного.
- ❔ **Источники меток** (`EventTextSource`): `{имя}` — первый участник события, `{напарник}` — второй; `{лекарь}`, `{щит}`, `{решающий}` — id в данных события `medic`, `shield`, `leader`; названия — `party`, `place`, `enemy`, `client`, `cargo`, `decree`, `building`; числа — `count`, `total`, `amount`, `income`, `expense`; `{архетип}` — название в роде человека. Человек ищется среди активных, в архиве и среди кандидатов.
- ❔ **Падежи** — у имён из `NameList` через `DataRegistry.NameForms`; нет формы — именительный. Не склоняются мужские имена на -о и -и (Отто, Бодо, Мирко, Стойко, Иржи) и женские на согласную (Агнеш, Ингрид, Катрин); Добрило склоняется как Данила. У названий заказов пока только именительный.
- ❔ **Заглавная буква**: значение в начале предложения пишется с заглавной («Медведь-шатун напал…»).
- ❔ **Скобка без владельца** (нет человека в предложении, метки `@` нет в строке) — мужская форма и `Error` в лог.
- ❔ **Условия шаблонов** — `Archetype`, `RevealedAxisPole`, `RevealedTrait` (это «RequiresRevealed»), `MaimedStat`. У условий заданий (`Solo`, `Group`, `Far`, `Near`, `QuestType`) проверки по событию пока нет: шаблон с ними не выбирается.
- ❔ **Шаблон ленты задания** на событие гильдии — `Error` в лог, строки нет: ведётся только лента гильдии.
- ❔ **Правки текстов по ходу**: «пришёл[|ла] новичок» → «приш[ёл новичок|ла новенькая]»; скобки с беглой гласной — полными формами (`уш[ёл|ла]`, `од[ин|на]`, `прощ[ён|ена]`, `наш[ёл|ла]`, `вы[шел|шла]`); «{имя} первым» → «перв[ым|ой]»; глаголы при `{враг}` и `{заказчик}` — со скобкой рода названия.
- ❔ **Сводка**: столбцы «Лента [О]», «Лента [З]», «Лента [В]» — строк за месяц (сумма за прогон).
