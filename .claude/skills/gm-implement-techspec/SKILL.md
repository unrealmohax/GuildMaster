# Реализация ТЗ (GM-XX)

## 0. Рамки

- Запущенное ТЗ — разрешение менять код и ассеты **в его рамках**. Другая подсистема, смена архитектуры, отступление от ТЗ —
  предложить и ждать. ТЗ противоречит дизайну или его не хватает — остановиться и спросить.
- Ветка `GM-XX_краткое_название` от `develop` (если её нет — предложить создать). Коммиты — только по просьбе, метка `[GM-XX]`,
  без `Co-Authored-By`.
- Прочитать: `TechJob/NN-*.md` целиком (разделы «Опирается на», «Доработка готового кода», «Проверка», «Критерии приёмки»,
  «Открытые вопросы»), связанные `docs/mechanics/*.md`, `docs/content/numbers.md`, свежие строки `docs/decisions.md`,
  `TechJob/README.md` («Словарь кодовых имён», «Сводный список допущений»).
- Загрузить скиллы затронутых подсистем (`gm-simulation-core`, `gm-data` и профильные).

## 1. Чек-лист точек касания новой механики

Пройти по списку и отметить, что нужно этому ТЗ:

| Что | Где | Скилл |
|---|---|---|
| Числа баланса (новый раздел/поля, значения по умолчанию = документ) | `Data/Balance/*Balance.cs` | `gm-data` |
| Определения и их поля, заполнение | `Data/Definitions/`, `ClaudeSandbox/Editor/GameDataGenerator*.cs`, `GameConfig` | `gm-data` |
| Часть мира (internal-сеттеры, `IReadOnlyList`) | `WorldState` + список в `ArchitectureTests` | `gm-simulation-core` |
| Система и её место в такте | `SimulationSystems.CreateDefault()` (комментарий 16 шагов) | `gm-simulation-core` |
| Службы с `SimContext` для мутаций | `Core/<Подсистема>/…Service.cs` | — |
| Команды игрока | `…Command : ICommand` | `gm-simulation-core` |
| События | конец `SimEventType` | `gm-simulation-core` |
| Автопауза | `AutopauseRules.Default` (+ `AutopauseKind`) | `gm-simulation-core` |
| Уровень лога частых событий, строки лога решений/бросков | `EventLogLevels`, `ctx.RollChance`, `Log.Write<…>` | `gm-debug-headless` |
| Строки ленты: ключи, шаблоны, метки, условия | `FeedKeys`, генератор `.Feed.cs`, `EventTextSource`, `TextPlaceholders`, `FeedConditions` | `gm-feed-text` |
| Тексты причин (`reason.*`) | `Keys` класса причин + шаблоны | `gm-feed-text` |
| Статьи журнала казны | `LedgerCategories` + `ledger.*` | `gm-economy` |
| Отчёт месяца: раздел/строки | `MonthReportSections.Default` + `report.*` | `gm-economy` |
| Модель решений: действие, точка, запрет | `DecisionActions`, `DecisionPoints`, `DecisionBans` | `gm-decisions` |
| Эффекты черт, кодовые правила, раскрытия | `TraitEffect`, `TraitHook`, `RevealTrigger` (в конец enum) | `gm-adventurers` |
| Проверки валидатора | `DataValidator` | `gm-data` |
| Сводка прогона: столбцы | `SummaryColumns.Monthly` / `People` | `gm-debug-headless` |
| Команда сценария, правило бота «Простой» | `ScenarioCommands.Formats`, `PlayerBots.Presets` | `gm-debug-headless` |
| Зонд для проверки глазами | `ClaudeSandbox/Editor/…Probe.cs` + README песочницы | `gm-debug-headless` |

Правила кода: комментарии без ссылок на ТЗ, документы и даты; числа только из `BalanceSettings`; в Core — только `ctx.Rng`;
порядок бросков существующих систем не менять без причины; «пустой» случай новой механики бросков не тратит.

## 2. Проверка

1. После правки скриптов — дождаться компиляции, `read_console` (ошибки и предупреждения).
2. Если менялся генератор — GuildMaster → Sandbox → Generate Game Data, затем GuildMaster → Validate Data (0 ошибок, 0 предупреждений).
3. Тесты EditMode — все (`run_tests`). Новые тесты: механика, детерминизм («одно зерно — один лог»), «не сдвигает чужие броски»
   (скилл `gm-testing`). Упавшие старые — разобрать причину, не подгонять вслепую.
4. Прогон серии: GuildMaster → Sandbox → Headless → `Year Seeds 1-10 Info` (или окно Run Headless…) — сравнить сводку с прошлыми
   цифрами в таблице «Прогоны года: базовые цифры» архитектурного `CLAUDE.md`; время года.
5. Критерии приёмки ТЗ — пройти по пунктам.
6. MCP-хозяйство: всё временное удалено, сцена не сохранена без нужды, файлы `Logs/` удалены, Play Mode и `runInBackground` возвращены.

## 3. После

- Скилл подсистемы в `.claude/skills/` — обновить или завести новый (карта файлов, ход, рецепты, ловушки). Изменённое
  поведение старых подсистем — в ловушки их скиллов; изменённые старые тесты и причины — в отчёт и сообщение коммита.
- `game/Assets/_Project/CLAUDE.md` — коротко: задание в списке вверху, «Где что лежит», порядок систем в «Сквозных правилах»,
  строка в таблице «Подсистемы — в скиллах», строка в «Прогоны года: базовые цифры», число тестов. Подробности — только в скилле.
- Корневой `CLAUDE.md` — новый скилл в таблицу `.claude/`.
- `docs/decisions.md` — решения пользователя (строкой в начало); `docs/open-questions.md` — закрытые вопросы; ✅ только за явно
  утверждённое, своё — 💡/❔.
- `TechJob/NN` и `TechJob/README.md` — допущения, принятые при реализации; поправить затронутые ТЗ с большим номером.
- `ClaudeSandbox/README.md` — новые зонды.
- Отчёт пользователю: что сделано, что изменено в ассетах и на диске, итоги тестов и прогона, открытые вопросы.
