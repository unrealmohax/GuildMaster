# ТЗ 08. Заказы и доска

Дизайн: [quests.md → Генерация заказов](../docs/mechanics/quests.md#генерация-заказов), [core-loop.md](../docs/core-loop.md). Числа: [numbers.md → Задания](../docs/content/numbers.md#задания).

## Цель

Заказы появляются каждое утро, Регистратор ставит обычные на доску по правилам игрока, важные передаёт игроку. Авантюристы берут заказы с доски сами.

## Модель данных `Order`

| Поле | Что это |
|---|---|
| `Id`, `TypeId` | Охота, истребление, сопровождение, доставка |
| `Client` | Заказчик (горожанин, купец, крестьянин — из `OrderTextTemplates`) |
| `Rank` | G–C |
| `Profile` | float[13] — скрытый профиль требований по осям диаграммы |
| `PartySizeCeiling`, `StatCeilings` | Скрытые потолки |
| `Description`, `HintStats` | Текст для игрока и людей, какие оси в нём намекнуты |
| `DescriptionAccuracy` | Скрытый множитель 0,9–1,1: насколько описание недооценивает / переоценивает задание |
| `Reward`, `Surcharge` | Награда заказчика и доплата гильдии |
| `Distance` | `Near` / `Far` |
| `ExpiresAtHours` | Когда снимут с доски |
| `Status` | `Incoming` → `OnBoard` / `AwaitingPlayer` → `Taken` → `InProgress` → `Done` / `Failed`; или `Declined`, `Expired` |
| `Flags` | `IsImportant`, `IsHardEarly` (сложный не по времени), `IsPromotion` (+ `OwnerId`), `IsEventQuest` |

## Генерация (каждый день в 06:00)

1. **Количество**: `1 + репутация / 10`; дробная часть — шанс ещё одного заказа.
2. **Ранг** по смеси для текущей репутации ❔:

| Репутация | G | F | E | D | C |
|---|---|---|---|---|---|
| 0–20 | 85% | 15% | — | — | — |
| 20–40 | 20% | 50% | 30% | — | — |
| 40–60 | — | 10% | 50% | 40% | — |
| 60+ | — | — | 20% | 50% | 30% |

   С шансом **5%** заказ — **сложный не по времени**: ранг +2 к выпавшему (не выше C).
3. **Тип** ❔: охота 30%, истребление 25%, сопровождение 20%, доставка 25%.
4. **Расстояние** ❔: близко 70%, далеко 30%.
5. **Профиль**: главные оси типа — `Range(главные[ранг])`, второстепенные — `Range(второстепенные[ранг])`, остальные — 0; каждая ось × `Range(0,8; 1,2)`; затем **все оси не меньше 10** (минимальный порог, ТЗ 09). ❔ Далеко: если Выживания нет среди осей — добавить как второстепенную.
6. **Потолки**: из типа (доставка — не больше 3 человек).
7. **Награда**: `Range(награда[ранг])`, далеко × 1,5, округлить до 5.
8. **Срок на доске**: 3–7 дней.
9. **Описание** (ниже), `DescriptionAccuracy = Range(0,9; 1,1)`.
10. **На старте игры** ❔ — 3 заказа ранга G уже на доске.

Шаблоны профилей по типам — [quests.md](../docs/mechanics/quests.md#генерация-заказов).

## Описание

- Шаблон из `OrderTextTemplates` для типа: «{Заказчик} просит {действие} у {место}».
- **Намёки** на 1–2 самые большие оси профиля (строки на каждую ось в `OrderTextTemplates.hints`):

| Ось | Пример намёка |
|---|---|
| Наблюдательность | «Говорят, зверь хитёр и осторожен» |
| Сила / Выносливость | «Их там целая стая» |
| Меткость | «Близко к нему не подойти» |
| Знания | «Никто толком не знает, что это за тварь» |
| Выживание | «Дорога идёт через глушь» |
| Реакция | «Нападает внезапно» |
| Скрытность | «Лишнего внимания не нужно» |

- Далеко — «Путь неблизкий». Доставка с потолком — «Лишнего внимания не нужно».
- ❔ 30 строк намёков — черновик, заполняет автор.

## Регистратор и важные заказы

- **Важный заказ** ❔: `IsHardEarly` или награда ≥ `importantRewardThreshold` (250).
- **Обычный заказ** Регистратор проверяет по **правилам игрока**:
  - какие типы брать (переключатели по 4 типам);
  - до какого ранга брать сам;
  - минимальная награда.
  Подходит → `OnBoard`. Не подходит → `Declined` (строка в ленте гильдии [О]).
- **Важный заказ** → `AwaitingPlayer`: уведомление, игрок **принимает** (можно сразу назначить доплату) или **отклоняет**. ❔ Без ответа 2 дня — отклонён.
- Правила Регистратора и комиссия меняются командами (экран «Доска», ТЗ 15).

## Доска

- Игрок видит: тип, заказчик, ранг, расстояние, награда, доплата, описание, сколько осталось висеть, кто взял. **Профиль не виден никогда.**
- Игрок может **назначить доплату** любому заказу на доске (из казны при выплате, ТЗ 10).
- Непопулярный заказ снимается по сроку: `Expired`. В прототипе все заказчики — горожане, последствий нет.

## Особые заказы

- **Задание на повышение** (ТЗ 09): личное, видно только владельцу, ранг = следующий ранг владельца, тип случайный, ❔ награда как у обычного заказа этого ранга.
- **Событийное задание** из находки (ТЗ 09): игрок назначает ранг G–C → от него награда и кто может взять; настоящий профиль — от «истинного» ранга находки, скрыт.

## Критерии приёмки

- [ ] Заказы появляются в 06:00 в нужном количестве и смеси рангов по репутации.
- [ ] Профиль собирается по шаблону типа, скрыт от игрока.
- [ ] Описание содержит намёки на главные оси.
- [ ] Регистратор ставит на доску по правилам, важные уходят игроку, без ответа — отклоняются.
- [ ] Доплата прибавляется к доле авантюристов и списывается из казны при выплате.
- [ ] Просроченные заказы снимаются.

## Открытые вопросы

- ❔ Смесь рангов по репутации, доли типов и расстояний, порог «важного», срок ответа игрока, стартовые заказы.
- ❔ Тексты намёков.
