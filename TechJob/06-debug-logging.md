# GM-06. Лог и прогон без интерфейса

| Задача | Ветка | Метки коммитов |
|---|---|---|
| **GM-06** | `GM-06_debug_logging` | `[GM-06]` — код, `[TechSpec-06]` — правки этого ТЗ |

Дизайн: [prototype.md → Этапы](../docs/prototype.md#этапы) (этап 1 — «ядро симуляции без интерфейса, проверка по логу»).

## Цель

Проверять симуляцию без интерфейса: прогонять месяцы за секунды, читать подробный лог, повторять ситуации по зерну, собирать цифры для баланса.

## Опирается на

- GM-01: `Simulation`, такт, `SimEvent`, команды, генератор с зерном, заготовка `HeadlessRun` и окна **Run Headless…**.
- GM-03–05: время, люди, состояние и здоровье — то, что сейчас есть в мире.

## Лог симуляции

- Класс `SimLogger` в `GuildMaster.Core`, пишет в файл и (по флагу) в консоль Unity.
- Каждая строка: `[Год.Месяц.День ЧЧ:00] [Система] [Уровень] текст`.
- **Уровни**: `Error`, `Info` (важное: события, решения, деньги), `Debug` (все броски: шанс, выпавшее число, итог), `Trace` (промежуточные расчёты).
- Логгер доступен всем системам через `SimContext`; выключенный уровень не строит строку (прогон на `Info` не должен тормозить из-за `Trace`).
- Файл: `Logs/sim_{зерно}_{дата}.log` в папке проекта (вне Assets).
- ❔ **Служебные события времени — ниже `Info`**: начало суток — `Debug` (разделитель дней среди бросков), часы и фазы дня — `Trace`. Иначе на `Info` за год ~10 тыс. строк о ходе часов. Остальные события — `Info`; новое частое событие опускается одной строкой в таблице уровней.
- ❔ **Событие пишется сразу после шага системы**, которая его опубликовала, — вслед за её бросками. Первая строка лога — параметры прогона (зерно, дней, бот, уровень); команды бота — строками `Info` от имени `Bot`.

### Что пишется сейчас

| Уровень | Что |
|---|---|
| `Info` | Все `SimEvent` систем GM-03–05: начало месяца, кандидат пришёл / ушёл / принят, раскрытие черты, смена архетипа, срыв, запой, уход, рана и выздоровление, пустой кошелёк |
| `Debug` | Броски: срыв, уход, осложнение раны, приход кандидата, генерация человека (тип, уровень). ❔ Ещё — пропуск дня Пьяницы, исход спада Потерявшего товарища, рана в драке (по правилу «`Debug` — все броски»). В строке броска — показатель, от которого зависит шанс (стресс для срыва, лояльность для ухода) |
| `Trace` | Показатели каждого человека раз в сутки: усталость, стресс, довольство и его цель, лояльность, кошелёк. ❔ Ещё — занятие, флаги (пустой кошелёк, срыв), долг, раны с остатком срока |

- **Скрытое тоже в лог**: значения осей характера, скрытые черты (при генерации человека — `Debug`). ❔ Там же — параметры, архетип, пол, возраст, кошелёк и стартовое состояние; стартовая шестёрка — после раздачи черт и пар, «старые друзья» — отдельной строкой.

## Прогон без интерфейса

Editor-окно **GuildMaster → Run Headless…**

| Поле | По умолчанию |
|---|---|
| Зерно | случайное (показывается) |
| Дней | 360 |
| Уровень лога | Info |
| Бот игрока | «Простой» |
| Число прогонов | 1 (для статистики — до 100 с разными зёрнами) |

- ❔ Умолчания и предел окна (360 дней, до 100 прогонов) — настройки инструмента, а не баланс: хранятся в окне, не в `BalanceSettings`.
- ❔ **Зёрна серии**: прогон `i` идёт с зерном `зерно + i`.
- ❔ **Файлы на каждый прогон**: лог, сводка `summary_{зерно}.csv` и сценарий команд бота `scenario_{зерно}.txt`; при нескольких прогонах — ещё `summary_{зерно}_x{N}.csv` со средними и разбросом.
- ❔ В окне — флаг «Лог в консоль» (по умолчанию выключен) и кнопка «Открыть папку Logs».

### Бот игрока

Бот отдаёт те же команды, что и игрок, через очередь команд (GM-01). Правила бота — отдельные классы, их список расширяемый.

- **Пассивный**: ничего не делает (проверка «мир живёт сам»).
- **Простой** ❔: принимает всех кандидатов в авантюристы.
- **Сценарий**: список команд «в такт N сделать X» из текстового файла — для повторения конкретной игры.
- ❔ Бот ходит перед каждым тактом; команда применяется в начале этого такта.

#### Формат сценария ❔

- Строка на команду: `такт слово аргументы`, например `672 accept 7`. Такт — сколько тактов сделано к моменту отправки (счёт с нуля); такты не убывают.
- Команды: `accept <ид кандидата>`, `reject <ид кандидата>`, `autopause <вид> on|off`. Новая команда игрока — строка в списке форматов.
- `#` — комментарий; `# seed=N` — зерно, с которым сценарий записан (ид кандидатов зависят от зерна). Окно берёт зерно из сценария и предупреждает, если оно отличалось от заданного.
- Сценарий пишется из команд бота каждого прогона; команду, которую формат не знает, — комментарием с пометкой «сценарий игру не повторит». Ошибка разбора — с номером строки.

### Сводка прогона

После прогона — файл `Logs/summary_{зерно}.csv` и таблица в окне. Столбцы сводки — расширяемый список: каждый столбец — имя и функция от мира (за месяц или на конец прогона).

- **По месяцам**: людей в гильдии, пришло / ушло, срывов, ран, раскрытых черт, средние усталость / стресс / довольство / лояльность, средний кошелёк, у скольких кошелёк пуст.
- **По людям**: архетип, ранг, ран, в гильдии ли на конец, какие черты раскрылись и когда.
- При нескольких прогонах — средние и разброс.

Допущения ❔:

- **Строка — календарный месяц**: значения берутся по миру в последний час месяца, счётчики — по событиям месяца. Последний неполный месяц идёт в сводку, если в нём прошли целые сутки (360 дней со старта в 06:00 — ровно 12 строк).
- **Средние и «кошелёк пуст»** — по людям в гильдии на конец месяца, не за весь месяц.
- **«Пришло»** — принятые в гильдию; отдельный столбец «Кандидатов» — сколько кандидатов пришло. **«Ушло»** — события ухода.
- **Раскрытия** — два столбца: «Раскрыто осей» (полюс и «уравновешен») и «Раскрыто черт» (особые черты).
- **Итог прогона** — строка «Итого»: счётчики суммируются, средние усредняются по месяцам, «людей» и «пустых кошельков» — на конец.
- **По людям** — все, кто был в гильдии (в гильдии и ушедшие); кандидаты, которых не приняли, не входят. «В гильдии» — «да» или «нет: причина дата»; раскрытия — «название дата» по порядку.
- **Разброс** — стандартное отклонение выборки; в свёртке ещё минимум и максимум по месяцам и по итогу, плюс итог каждого прогона.
- **CSV**: запятая между полями, точка в числах, UTF-8 с меткой BOM (кириллица в Excel); таблицы (прогон, месяцы, люди) — одна за другой через пустую строку. Excel с русской локалью может открыть файл в один столбец — тогда импорт с разделителем «запятая».

## Критерии приёмки

- [ ] Прогон 360 дней без UI меньше чем за минуту, с логом и сводкой.
- [ ] Одно зерно + тот же бот → одинаковый лог.
- [ ] Сценарий команд воспроизводит игру.
- [ ] По логу можно восстановить, почему у человека случился срыв или уход (показатели, броски).
- [ ] Прогон на уровне `Info` заметно быстрее, чем на `Trace`. ❔ Сравнивается цена лога — время сверх прогона без лога: на `Info` она в пределах шума, на `Trace` — заметна.
