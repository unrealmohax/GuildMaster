# ClaudeSandbox

Песочница Claude: вспомогательные скрипты, генераторы, дампы, замерочные инструменты, черновики.
Версионируется в git. В код проекта что-либо отсюда переезжает **только по прямому указанию** (см. корневой `CLAUDE.md`).

## Содержимое

### `Editor/GameDataGenerator*.cs` — генератор данных прототипа (GM-02)

Меню **GuildMaster → Sandbox → Generate Game Data**. Заводит и заполняет все ассеты в `Assets/_Project/Data/`
по документам (numbers.md, trait-effects.md, archetypes.md, quests.md, event-feed.md, ТЗ 04–14) и собирает `GameConfig`.

- **Перезаписывает целиком** определения, шаблоны ленты, имена и тексты заказов — правки, сделанные руками
  в этих ассетах, пропадут. После ручной правки данных генератор не запускать (или сначала перенести правку в него).
- **`BalanceSettings` не перезаписывает**: числа в ассете остаются как есть; новые разделы, которых в ассете ещё нет,
  получают стартовые значения из кода (поля по умолчанию) и сохраняются на диск.
- Приватные поля ставит отражением: у классов данных нет сеттеров — и не должно быть.
- Части: `GameDataGenerator.cs` — параметры, оси, черты, архетипы, типы заданий (с GM-11 — и «Исследование пещеры»,
  `CaveExploration`: вес генерации 0, тип событийного задания пещеры), события, постройки, персонал, распоряжения; `.Dilemmas.cs` — дилеммы (GM-17: флаги памяти Влюблённых ставят сами эффекты разрешения и запрета); `.Feed.cs` — шаблоны ленты (с падежами и привязкой `@`, GM-07) и тексты причин ухода `reason.*` (GM-08; строка ухода — с `{причина}`), подписи отчёта месяца `report.*` и названия статей журнала казны `ledger.*`, строка закрытия гильдии `guild.closed` (GM-09), строки доски `guild.board.*` и подписи разделов «Заказы» и «Репутация» (GM-10);
  строки заданий (GM-11, 💡): варианты для одного человека (условие `Solo`), экзамен, раунды пещеры, заказ взят по типам,
  экзамен и ранг, отказ по Кошмарам, бегство, беглец вернулся / исчез, причины `reason.fled` / `reason.nightmares`, раздел
  отчёта «Задания», статьи журнала «Комиссия», «Возврат долгов», «Доплаты», «Событийные задания», «Находки»;
  `.Texts.cs` — имена с шестью падежами (правила склонения и список несклоняемых — там же) и тексты заказов (💡 предложение):
  заказчики, места, враги, грузы — все шесть падежей вручную (GM-10).
- GM-17 (💡): статьи журнала «Займы авантюристам», «Обращения», «Штрафы», раздел отчёта «Обращения», строка «ушёл из группы: гильдия
  не велела ходить вместе»; числа цепочки прощённого беглеца — новые поля `DilemmasBalance` (в ассет — значения по умолчанию).
- После запуска — **GuildMaster → Validate Data** (или тест `DataValidatorTests.RealConfig_HasNoErrors`).

### `Editor/TimeProbe.cs` — время в Play Mode из меню (GM-03)

Меню **GuildMaster → Sandbox → Time**: `Log State` (время, фаза, такты, пауза, скорость, кадр), `Toggle Pause`,
`Speed 1/2/3`, `Debug Speed`. Нужен для проверки через MCP (`execute_menu_item`), где горячие клавиши не нажать.

- Редактор без фокуса не крутит кадры Play Mode: в настройках проекта `runInBackground` выключен.
  `Toggle Run In Background` включает его на время проверки. **В редакторе это меняет и `PlayerSettings` в памяти** —
  перед выходом из Play Mode выключить тем же пунктом (в лог пишутся оба значения) и проверить, что
  `ProjectSettings.asset` на диске не изменился.

### `Editor/AdventurerProbe.cs` — люди гильдии из меню (GM-04)

Меню **GuildMaster → Sandbox → Adventurers**: `Log Roster` (активные, кандидаты, отношения: параметры, оси с пометкой
раскрытия `!`, черты с партнёром и пометкой «скрыта»), `Accept First Candidate`, `Reject First Candidate` — в Play Mode;
`Preview Start Lineups` — стартовые шестёрки для зёрен 1–3 без Play Mode (симуляция в памяти, сцена не трогается).
Пишет через `Debug.Log` — в MCP читать `read_console` с `types: ["all"]`.

Там же (GM-05) — строка состояния у каждого: занятие, усталость, стресс, довольство, лояльность (числом и словами),
кошелёк, долг, флаги, раны.

### `Editor/StateProbe.cs` — состояние и здоровье из меню (GM-05)

Меню **GuildMaster → Sandbox → State**: `Light Wound First`, `Heavy Wound First`, `Stress +50 First` — первому в гильдии,
командой (как это будет вызывать ТЗ 11), в Play Mode; `Preview 90 Days` — 90 дней для зёрен 1–3 без Play Mode
(симуляция в памяти, кандидаты принимаются): счётчики событий систем состояния и состояние каждого в конце.
Пишет через `Debug.Log` — в MCP читать `read_console` с `types: ["all"]`.

### `Editor/HeadlessProbe.cs` — прогон без интерфейса из меню (GM-06)

Меню **GuildMaster → Sandbox → Headless**: `Year Seed 1 Debug`, `Year Seed 1 Trace` — год с ботом «Простой» в файлы;
`Year Seeds 1-10 Info` — серия из 10 лет (зёрна 1–10) со свёрткой. То же, что кнопка окна **Run Headless…**, но без
окна — для проверки через MCP (`execute_menu_item`). Файлы — в `Logs/` проекта (папка в `.gitignore`), пути и время —
в консоль (`read_console` с `types: ["all"]`). После проверки файлы прогона (`sim_*`, `summary_*`, `scenario_*`) удалить.
Сводка серии с GM-13 — ещё постройки (готовность, Общежитие, Лазарет, двор), персонал и долги по зарплате; бот строит и нанимает.
В меню `execute_menu_item` серии обрывает связь MCP на ~20 с (прогон в главном потоке) — дождаться файлов в `Logs/`.
`Year Seeds 1-10 Info With Decrees` (GM-16) — та же серия, но бот в первый такт включает все четыре распоряжения (Сухой закон — на 7 дней).

### `Editor/IncomeProbe.cs` — доходы и траты людей в неделю (GM-20)

Меню **GuildMaster → Sandbox → Headless → Income And Spending Per Week**: 10 лет (зёрна 1–10, бот «Простой»), каждая система такта
обёрнута замером кошельков (имя системы то же — мир не меняется). Статьи по системе и часу: награды и добыча, займы, пайки, еда,
жильё, семья, выпивка, Лазарет, двор, штрафы; на человеко-неделю — всего, по рангу на момент записи и по кварталам. Вывод — в
консоль (одной записью; полностью — в `Logs/Editor.log`), файлов нет. ~30 с, связь MCP на это время обрывается.

### `Editor/FeedProbe.cs` — лента событий из меню (GM-07)

Меню **GuildMaster → Sandbox → Feed**: `Dump Templates` — каждый вариант каждого шаблона для мужчины и женщины (Ян / Мара),
названия — метками падежа («место-р») во всех четырёх родах, ошибки подстановки — `!!`; `Year Feed Seed 1` — лента гильдии

в консоль. После проверки удалить.

### `Editor/QuestProbe.cs` — кто какие заказы берёт (GM-11)

Меню **GuildMaster → Sandbox → Quests → Order Preferences 10 Years**: 10 лет симуляции без игрока (зёрна 1–10), на каждое
взятие заказа — полюса осей Риск и Деньги взявшего, реальное перекрытие в одиночку (насколько заказ по силам) и награда

жадные — дороже бескорыстных. Около 10 секунд, файлов не пишет.

### `Editor/PartyProbe.cs` — группы (GM-12)

Меню **GuildMaster → Sandbox → Parties** (итог — в консоль построчно, `read_console` с `types: ["all"]`, фильтр `PartyProbe`;
файлов не пишет):

- `Groups 10 Years` — 10 лет с ботом «Простой» (зёрна 1–10) и тот же прогон «без групп» (копия данных в памяти, предел группы 1 —
  поведение GM-11): заданий соло / в группе, средний размер, выполнено, гибели, шанс раунда; «дыры» профиля — реальное перекрытие
  собранной группы против случайного набора того же размера из свободных людей нужного ранга; размер групп по тому, кто собрал
  (жадный / командный / одиночка); доля выходов соло по оси Люди; постоянные группы (сложилось, распалось, кто и почему ушёл); отказы
  от приглашений по причинам. Около 40 секунд.
- `Year Time With And Without Parties` — время года (зерно 1, лучший из трёх) с группами и без.
- `Trace Counts Seed 1` — сколько каких строк `Trace` за год (цена оценки групп).
- `Cost Benchmark` — цена отдельных расчётов: перекрытие, веса мотивов, синергии, ценность группы.

### `Editor/UiProbe.cs` + `FrameMeter.cs` — снимки экранов и замер кадра (GM-14)

Меню **GuildMaster → Sandbox → UI** (Play Mode): `Advance 45 Days` — перемотка сессии на 45 дней (GM-15); `Capture All 1920x1080` — Game view
в нужном размере и снимки всех экранов и окон (люди, постройки, персонал, группы, доска, задания, карточка, время, уведомления, отладка,
казна, кандидат, кандидат в персонал, отчёт, итоги поражения — предпросмотр, распоряжения, обращения, карточка обращения, вкладка «Поселение» (GM-21); окна решений из очереди перед съёмкой открываются и

`Log Screen State` — экран, окна, время, причины автопаузы; `Enable Sample Decrees` (GM-16) — включить «Только группой» (D, C),

командами вызвать просьбу в долг, Влюблённых и праздник Трактирщика (в обход условий); в `Capture All` — ещё экран «Обращения» и карточка. Снимки — `Logs/UiShots/`, после просмотра удалить.

(выключить до выхода из Play Mode). `FrameMeter` — компонент, который зонд добавляет в игре; в сцену не сохраняется.

### `Editor/BalanceProbe.cs` — замер баланса за 10 лет (первичный баланс)

Меню **GuildMaster → Sandbox → Balance**: `10 Years Seeds 1-3` / `1-5` — прогоны по 3600 дней ботом «Простой» без лога (~22 с на зерно).
Файлы — `Logs/Balance/{метка}/`: помесячная сводка `summary_N.csv`, годовая `yearly_N.csv` (люди по рангам, Сила, заказы, задания
и выполненные по рангам, средняя награда), свёртка `summary_1_xN.csv`, `done.txt` в конце. Метка — из `Logs/Balance/label.txt`
(нет файла — время запуска).
  GM-21: `10 Years Seeds 1-5 Passive Bot` — то же ботом «Пассивный» (5 зёрен); в `done.txt` — причина и дата закрытия, Безопасность,
  население, нападения, угрозы выполнено/упущено; в `yearly_N.csv` — Безопасность на конец года и минимум, худший уровень, население,

  Ещё `budget_N.csv` (`BudgetTracker.cs`) — доходы и расходы людей по статьям, году и рангу, человеко-часы на ранге; свёртка «на человека
  в неделю» — в `docs/content/balance-runs.md`.
  GM-22: `10 Years Seeds 1-3 Reckless Bot` — то же ботом «Безрассудный» (3 зерна). Сам бот уехал из зонда в код проекта —
  `PlayerBots.Reckless` (`Scripts/Debugging/Headless/PlayerBot.cs`), зонд только вызывает его.
  GM-23: в `yearly_N.csv` — ещё «Заданий», «Выполнено всего», «Блестяще», «Соло» / «В группе» / «Постоянной группой» и их выполнено,
  «Людей в группах» (средний размер группы = людей / заданий в группе), «Раундов» и «Раундов на потолке» (шанс = `maxRoundChance`),
  «Заданий-угроз» и «Угроз выполнено заданий». Элемент списка в переопределении — `rounds.groupContributionWeights.Array.data[1] 0.75`.
  GM-24: `10 Years Seeds 1-5 Smart Bot` — то же ботом «Умный» (5 зёрен); в `yearly_N.csv` — ещё «Набегов отбито», «Набегов проиграно»,

  (путь — как у `SerializedProperty`, например `ranks.ranks.Array.data[4].reward.max 240`, `Dormitory cost 1500`, `#` — комментарий).
  На время прогона числа меняются в памяти и возвращаются после (`overrides_applied.txt` — что применилось); ассеты не сохраняются.

  перенести и в генератор данных, иначе он их вернёт).
- Через MCP: `execute_menu_item` отвечает таймаутом или обрывом связи — прогон при этом идёт; ждать `done.txt`.

### `Blender/` — кит построек для 3D-вида поселения

`kit_build.py` строит в Blender (без окна) 88 модулей домов — стены с окнами пяти видов (обычное, закрытые ставни, ленточное, под козырьком, малое), глухие с ригелем, косым крестом или раскосом, столбы, каменный цоколь с окошком подвала, нижний этаж из камня или
штукатурки (арочная дверь, окно в каменном обрамлении, угловые камни), крыльцо, пыль и козырёк у двери, балки и кронштейны выступа этажа, навес на столбах, фронтоны с подкосами буквой V, сланцевые
крыши из отдельных плиток (три варианта клетки, коньковые плитки, слуховые окна двух видов) и соломенные под глубину 3–8, трубы, колышки, леса, разруху; у бруса, камня и досок фаски — выгружает каждый в FBX и рендерит превью: дома во всех стадиях с камеры вида поселения и лист модулей. Размеры, точки привязки
и имена модулей — договор с генератором в Unity, описан в `Blender/README.md`. Запуск — там же; превью кладутся вне репозитория
(`C:\AI\Concepts\Kit3D`).

### `Kit3D/` — генератор домов из кита

`Models/` — FBX модулей из `Blender/`; `HouseKit` — каталог «имя модуля → модель»; `HouseGenerator` — компонент, собирающий дом по ширине, глубине, этажам, сиду и стадии (заложен, строится, готов, заброшен) прямо в редакторе: меняешь поле — дом пересобирается, сборка в сцену не сохраняется. `KitTest.unity` — пробная сцена: ряд стадий (дома 6 × 6) и квартал случайных домов (5–10 клеток вдоль конька, 5–7 в глубину) с камерой вида поселения.

`Textures/` — фото-текстуры Poly Haven (CC0, 1K): `rough_wood` (брус, затемнён, по волокну растянут до 1,6 м — иначе повторяются сучки),
`medieval_wood` (дверь: вертикальные доски с гвоздями), `weathered_brown_planks` (доски и пол этажей), `white_stucco` и `white_stucco_02` (побелка заполнения
и оштукатуренного этажа — ровная и шершавая), `large_sandstone_blocks_01` (белый камень, сейчас не используется); `damaged_plaster` (побелка с кирпичом)
больше не используется; `medieval_blocks_03`
(кладка трубы, рельеф ослаблен до 0,35 — иначе поры рябят вблизи), `rock_01` (гладкий мелкозернистый камень: камни цоколя, крыльца, обкладок
и углов; с красно-бурым оттенком и рельефом 0,35 — плитки сланца, у каждой свой кусок текстуры); `rock_surface` (пористый) больше не используется,
`thatch_roof_angled` (соломенная); `grime/grime_gradient.png` рисует сам `Build Materials` — пыль у двери (прозрачный материал без блика:
с бликом лист светится дымкой и там, где пыли нет); `roof_slates_02` (дранка рисунком) больше не используется — сланец стал геометрией. У каждой — цвет, нормали (OpenGL)
и `arm`; `Build Materials` (`Editor/Kit3DMaterials.cs`) перепаковывает `arm` в `_mao` под URP Lit (R металл, G затенение, A гладкость),
создаёт материалы `Materials/GM_*` с повтором по реальному размеру текстуры (солома растянута до 1,5 м — иначе издалека шум) и прописывает
их моделям по имени слота (`GM_Roof` — сланец, `GM_Thatch` — солома). Блеск дерева из карты ослаблен (`gloss`), иначе фаски бруса дают
светлые полосы. Генератор сдвигает развёртку каждого модуля (кроме крыши) по месту клетки вдоль стены, высоте этажа и случайному сдвигу дома —
соседние клетки не повторяют один кусок текстуры; копии мешей кэшируются так же, как у крыши.

Облик дома — по сиду своим потоком, не сдвигая броски стен: солома или сланец (`thatchChance`, у заброшенных — всегда солома), выступ верхних
этажей (`jettyChance`, у домов в 2–3 этажа глубиной до 7), провис конька; третьим потоком — нижний этаж (`plasterChance`, `stoneChance`,
только у готовых домов) и окно подвала (`cellarChance`). Провис и бесшовную текстуру по всей крыше генератор делает копиями мешей
крыши (вершины опущены по параболе вдоль дома, развёртка сдвинута на клетку); копии кэшируются на всё время редактора и в сцену не сохраняются.
Переимпорт модели меняет её сетку на месте, и дома продолжили бы собираться из копий старой геометрии — поэтому `Editor/Kit3DModelImport.cs`
после импорта любой модели из `Models/` сбрасывает кэш копий и пересобирает дома на открытых сценах. Он же включает моделям
Read/Write: генератор читает развёртку и вершины модулей, а нечитаемая сетка после выгрузки и повторной загрузки остаётся без данных
на процессоре — тогда пересборка дома (например, при смене размера) падала с ошибкой `Not allowed to access uv`.

Шейдеры старения в `Shaders/` — на основе URP Lit: общие `KitLitInput.hlsl` (входные данные Lit; свои числа шейдер кладёт в общий буфер
материала макросом `KIT_MATERIAL_PROPERTIES`, поэтому SRP Batcher работает), `KitForwardPass.hlsl` (проход освещения; поверхность меняет
макрос `KIT_APPLY_SURFACE` шейдера) и `KitNoise.hlsl` (шум значений); остальные проходы — из URP.

Мох на сланце — шейдер `Shaders/RoofMoss.shader` («GuildMaster/Kit3D/Roof Moss»), поверх плитки — текстура мха
`forest_leaves_02` (Poly Haven, CC0, 1K, 0,25 м на копию; оттенок приглушён в оливковый — сама текстура в рыжих сухих листьях). Мох растёт
только на гранях, смотрящих вверх, редкими пятнами от зародышей: мир по XZ поделён на клетки 2,5 м, в 40% клеток — зародыш в своей точке,
со своим радиусом (1–2 м) и возрастом начала роста; пятно расползается от него во все стороны с рваным краем. Внутри пятна мох лежит клочками
(плотность 0,5), сквозь них видна плитка; под пятном плитка чуть темнее — сырость. Крыша целиком не зарастает и при наибольшем возрасте.
Числа мха подобраны автором в материале; `Build Materials` их перезаписывает — подобранное вживую переносить в `Kit3DMaterials.cs`.
Насколько заросла крыша — `_Growth` (0..1). У `HouseGenerator` ползунок **Age** (0 — новая, 1 — пятна наибольшие; пристройка берёт возраст дома):
генератор ставит дому копию материала с `_Growth` по возрасту, копии общие на 20 ступеней возраста (дома одного возраста батчатся вместе)
и в сцену не сохраняются. Солома не зарастает — у неё свой материал. `Build Materials` ставит `GM_Roof_Slate` этот шейдер и текстуры мха.

Побелка — шейдер `Shaders/PlasterWear.shader` («GuildMaster/Kit3D/Plaster Wear»): с износом `_Wear` (0..1) побелка темнеет пятнами грязи
и осыпается до дерева обрешётки `rough_wood` (1,5 м на копию, светлый холодный оттенок — подобраны автором). Сколы растут от источников
на плоскости стены: она поделена на клетки `_WearSpacing` (1,2 м), в доле клеток `_WearSources` (0,4) есть источник со своим радиусом
(до `_WearRadius`, 0,6 м) и своим износом, с которого он начинает расти; у каждой стены свои источники, внизу стены сколы крупнее
(`_WearLow`). Край скола местами резкий — с тенью (`_WearShade`) и тёмной каймой, — местами плавный: побелка истончается до
`_WearSoft` (0,15 м) и сквозь неё проступает дерево; где какой — решает мировой шум. Край рваный по рисунку побелки. Два материала —
`GM_Daub` (ровная `white_stucco`) и `GM_Daub_Rough` (шершавая `white_stucco_02`); `Build Materials` ставит им шейдер и одни и те же числа
и кладёт оба в каталог кита (`HouseKit` → Plasters). В модулях стоит `GM_Daub`, генератор заменяет его побелкой, выпавшей дому по сиду
(свой поток; пристройка берёт побелку дома). У `HouseGenerator` ползунок **Wear**
(0 — стена целая, 1 — осыпалась), у заброшенного дома износ полный всегда; копии материала — как у мха, на 20 ступеней.
Кладка `GM_Stone` (труба, каменный этаж) — числа автора: 0,85 × 0,82 м на копию, сдвиг по V 0,08 (`Textured` умеет сдвиг), рельеф 0,75.
Пол этажей — не модуль кита: генератор сам строит на каждый этаж готового или заброшенного дома и на чердак (по размеру верхнего этажа) плиту из досок `GM_Floor`
(`weathered_brown_planks`, 1,8 м на копию — число автора; доски вдоль конька). Плита 8 см, верх на 1 см выше цоколя и нижнего бруса стены,
края уходят в стены на 0,1 м, у пристройки со стороны дома — до его стены; снизу она же — потолок нижнего этажа. У строящегося дома пола нет.
`Build Materials` кладёт `GM_Floor` в каталог кита (`HouseKit` → Floor).

`Lighting/` и `Editor/Kit3DLighting.cs` — свет пробной сцены под пасмурный концепт: небо `OvercastSky`, рассеянный свет трёх цветов, мягкое солнце,
дымка, объём постобработки `OvercastVolume` (ACES, приглушённый цвет, холодный баланс белого, виньетка, слабое свечение); камеры
`Settlement Camera` (вид поселения) и `Detail Camera` (вблизи, выключена — снимок через MCP по имени камеры). **Apply Lighting** — свет в
загруженную `KitTest` (можно рядом с другой сценой; освещение — у активной сцены, для снимков её делать активной). **Apply Render Settings** —
настройки проекта: SSAO в `UniversalRenderer`, мягкие тени и два каскада в `UniversalRP`. **Build Test Scene** отказывается работать, если в
открытой сцене есть несохранённые правки (новая сцена закрыла бы её без вопроса).

Меню GuildMaster → Sandbox → Kit3D: **Build Kit Catalog** (каталог по папке моделей), **Build Test Scene** (пересоздать пробную сцену), **Build Materials** (материалы из текстур и подмена ими материалов FBX), **Rebuild Houses**, **Re-lay Test Houses** (заново расставить дома пробной сцены в активной сцене по текущим размерам, не трогая землю, свет и камеры), **Log Module Bounds** и **Log Houses** (габариты модулей и что собрал каждый дом — в `Temp/`, потому что `Debug.Log` через MCP не виден).
