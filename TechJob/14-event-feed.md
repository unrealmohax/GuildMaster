# GM-14. Лента событий

| Задача | Ветка | Метки коммитов |
|---|---|---|
| **GM-14** | `GM-14_event_feed` | `[GM-14]` — код, `[TechSpec-14]` — правки этого ТЗ |

Дизайн: [quests.md → Лента событий](../docs/mechanics/quests.md#лента-событий). Шаблоны: [event-feed.md](../docs/content/event-feed.md).

## Цель

Превращать события симуляции в короткие строки-хронику на русском: две ленты, три уровня важности, варианты по чертам и архетипу, без выдачи скрытых черт.

## Модель данных `FeedEntry`

| Поле | Что это |
|---|---|
| `TimeHours` | Когда |
| `Feed` | `Quest` (+ `QuestRunId`) или `Guild` |
| `Importance` | `Normal` [О], `Notable` [З], `Important` [В] |
| `Text` | Готовая строка |
| `Links` | Id людей, задания, обращения — для перехода по клику |
| `TemplateKey` | Для отладки |

- ❔ Лента гильдии хранит последние 500 строк; лента задания — всё задание и 30 дней после возвращения.
- ❔ **Важные** строки заданий (гибель, бегство, отступление, катастрофа, раскрытие) дублируются в ленту гильдии.

## Путь от события к строке

1. Система публикует `SimEvent` (ТЗ 01, список типов — ТЗ 09 и другие).
2. `FeedSystem` по типу события берёт **ключ шаблона**.
3. Выбирает `FeedTemplate` по ключу, у которого выполнены **условия**; если подходят несколько — самый конкретный (больше условий).
4. Выбирает **случайный вариант** строки; ❔ не повторять последний использованный вариант этого ключа.
5. Подставляет значения, склоняет, ставит род.
6. Пишет строку в ленту и в лог симуляции (ТЗ 16).

## Условия шаблонов

| Условие | Пример |
|---|---|
| `Solo` / `Group` | «{имя} ушёл один» |
| `Far` / `Near` | «Третий день пути» |
| `Archetype(x)` | Вариант для Щита: «принял удар на щит» |
| `QuestType(x)` | Строки раундов по типам |
| `RequiresRevealed(черта или полюс)` | Строка, которая называет черту прямо |

**Скрытые черты не выдаются**: строка с условием `RequiresRevealed` выбирается только если черта уже раскрыта. Для нераскрытой — вариант, описывающий только поведение.

## Подстановки

| Метка | Что | Примечание |
|---|---|---|
| `{имя}`, `{напарник}`, `{лекарь}`, `{щит}`, `{решающий}` | Люди | Склоняются, задают род |
| `{группа}` | Группа | ❔ Всегда в форме «группа {имя:р}» или «группа «{название}»» — женский род, единственное число: «группа «Серые волки» вышла» |
| `{место}`, `{враг}`, `{заказчик}`, `{груз}` | Из заказа и `OrderTextTemplates` | Склоняются |
| `{число}`, `{сумма}` | Числа | |
| `{распоряжение}`, `{постройка}` | Названия | Склоняются |

### Падежи

В русских строках нужны падежи: «у {место}» → «у старой мельницы», «рядом с {напарник}» → «рядом с Марой», «У {имя}» → «У Яна».

- Метка с падежом: `{имя:р}` (родительный), `{имя:д}` (дательный), `{имя:в}` (винительный), `{имя:т}` (творительный), `{имя:п}` (предложный). Без буквы — именительный.
- ❔ У имён, мест, врагов, построек в данных хранятся **все шесть форм** (`NameList`, `OrderTextTemplates`, `BuildingDefinition`).
- **Нужно при заполнении данных**: расставить падежи в шаблонах [event-feed.md](../docs/content/event-feed.md). Например: «до {место:р}», «у {место:р}», «на {враг:в}», «рядом с {напарник:т}», «закрыл собой {напарник:в}», «У {имя:р} рассечена бровь», «без [него|неё]».

### Род

- Скобки `[м|ж]` — форма для мужского и женского рода: `заметил[|а]`, `испугал[ся|ась]`, `[он|она]`, `[его|её]`.
- **Чей род**: ближайшего **предыдущего** человека-метки в том же предложении; если перед скобкой человека нет — ближайшего **следующего**.
- Явное указание: `[его|её]@имя` — род `{имя}`. Нужно, например, в «{напарник} тащит [его|её]@имя на себе».
- Валидатор (ТЗ 02) проверяет, что у каждой скобки находится человек.

## Уровни важности

| Уровень | Вид (ТЗ 15) | Автопауза |
|---|---|---|
| [О] обычное | Серый текст | Нет |
| [З] заметное | Цветной текст | Нет |
| [В] важное | Крупно, значок | Если тип события в списке автопаузы (ТЗ 03) |

## Строки раскрытия черт

- Раскрытие — всегда [В]. Строка — из таблицы раскрытия в [event-feed.md](../docs/content/event-feed.md#раскрытие-черт).
- После строки раскрытия в карточке человека черта становится видна (ТЗ 04).

## Шаблоны для систем без строк в event-feed.md

❔ Добавить при заполнении данных: кандидат пришёл / ушёл; сотрудник нанят / уволился; стройка поставлена в очередь; найдено событийное задание; ответ на обращение (по строке на вариант); смена архетипа; появление и распад постоянной группы.

## Критерии приёмки

- [ ] Каждое событие из ТЗ 09–13 даёт строку в нужной ленте и нужной важности.
- [ ] Род и падежи правильные для мужских и женских имён (тест на всех шаблонах × 2 пола).
- [ ] Строки с названиями черт появляются только после раскрытия.
- [ ] Один и тот же вариант не повторяется подряд.
- [ ] Клик по строке ведёт к человеку, заданию или обращению.
